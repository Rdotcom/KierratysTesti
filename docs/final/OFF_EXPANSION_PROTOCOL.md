# Free OFF corpus expansion — metadata stage v1

2026-11-14. Extend coverage rather than repeat the completed recognition test.
Stable licences/old acquisition results are retained; new API availability is
revalidated because selected-front-only selection left Prince without a query
and Coca-Cola without enough references. No old ledger or denominator changes.

The unit of observation is `(source GTIN, numeric original upload ID)`, NOT a
crop, language view, image resolution or proven independent capture. Fetch
exactly the same five public product records, one serial APIv2GET each with
explicit fields and identifying project User-Agent.15s/512KiBresponse bounds,
no authentication, redirects, retries, image downloads or model calls. Record
raw bounded responses/hashes, transport failures and unavailable products.
Freeze source/prior-selection/protocol hashes and one canonical attempt before
requests. Access date comes from the client date, not an inferred capture date.

Inspect all numeric uploads, not only currently selected front-language views.
Require public contributor handle, sane nonfuture upload timestamp and available
400px dimensions; retain rejection reasons. Selected views must join a real
numeric parent. Keep community name/quantity changes visible; no image association
or source title is promoted to verified GTIN/physical-variant truth.

Conservatively cluster same-contributor uploads with adjacent gaps≤24h
transitively. Any cluster containing one of the21already-seen uploads is excluded
from new candidates. Also exclude same-author clusters overlapping the old
upload-day±1day interval, even if an old numeric upload has disappeared or its
current metadata was rejected. This is a leakage-reduction proxy, NOT proof of
independent photography or a new statistically held-out test.

Before any pixel/model result, choose at most six unseen families per product,
newest family first; choose its selected-front parent if present, otherwise its
first numeric upload. First two are reference candidates, third evaluation
candidate, remaining reserves NOT automatic substitutes. Every image still needs
actual visual privacy/whole-product/duplicate checking; metadata completeness
alone never qualifies a usable catalogue. Less than three families stays an
explicit unavailable/insufficient row, not a fabricated image or dropped SKU.

Store attribution/source snapshots under existing ODbL/DbCL/CCBY-SA3boundaries.
No new independent human checker is required(D-086); unobserved privacy,
source identity and capture independence remain explicit. Public contributor
metadata is retained only for attribution/leakage audit while the corpus is
retained. No personal contact information is selected as attribution.
